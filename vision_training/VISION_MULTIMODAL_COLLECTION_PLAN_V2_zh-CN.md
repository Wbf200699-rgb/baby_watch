# 视觉与多模态数据采集方案 V2

## 1. 结论

不能只收集“婴儿、毛毯、婴儿脸部”的静态图片。那只能改善目标检测和口鼻遮挡，不能可靠判断扒边、安静、活动或睡眠。

下一版应把任务拆成三层：

1. **单帧视觉只描述看得见的事实**：婴儿、头脸、毛毯、软物、照护者、姿态和口鼻可见性。
2. **时序层描述运动**：检测框轨迹、压力变化和热目标移动。
3. **融合层判断状态和风险**：扒边、活动、安静、睡眠、离床等结论不能由一张图片直接决定。

本方案的关键变化是：

- 停止把 `edge_grab` 当成婴儿 ROI 的普通单帧外观类别；
- 将现有行为模型改造成姿态模型；
- 将 `quiet / active` 移到时序融合层；
- 将“扒边”定义为“站立 + 位于床边 + 边缘载荷/向外运动”的持续组合证据。

## 2. 当前误判为什么会发生

当前训练说明把行为类别定义为：

```text
quiet, active, edge_grab, caregiver, unknown
```

但当前板端编译模型和运行时实际上是 4 类：

```text
quiet, active, edge_grab, unknown
```

编译产物的行为输出张量长度也是 4。训练配置、说明文档和部署模型类别不完全一致，下一轮训练前必须统一标签清单、类别顺序和版本号。

当前 CPU0 还会：

```text
edge_grab 概率 -> standing_confidence
active 概率    -> movement_confidence
quiet 概率     -> sleep_confidence
```

这三个映射中，只有“站立姿态”适合从单帧提取；活动和睡眠都必须观察一段时间。若训练集中 `edge_grab` 主要是“玩偶靠边、手臂靠床栏、上身在画面边缘”，模型会学习边缘背景和构图，而不是学习真正站立，所以任何靠边画面都容易被判为扒边。

需要区分两个显示值：

- 原始视觉行为类别可能单独显示 `edge_grab`；
- 当前融合层输出 `EDGE_GRAB` 还会检查压力边缘比例和婴儿框位置。

因此网页上频繁出现“扒边”时，要同时记录原始行为输出和最终融合状态，不能把二者混为一个标签。

## 3. V2 模型和规则边界

### 3.1 场景检测模型

保留当前五类框：

```text
infant
head_face
blanket
soft_object
caregiver
```

每张图允许同时出现多个类别。空床、只有被褥、照护者进入但没有婴儿，都要作为重要负样本。

床边安全区域使用固定相机下的几何 ROI 标定，不急于增加 `crib_rail` 类。只有相机经常移动时才考虑训练床栏检测。

### 3.2 口鼻遮挡模型

保留四类头部 ROI：

```text
clear
partial
covered
not_visible
```

标签只描述当前 ROI 是否看得见口鼻：

- `clear`：口鼻主要区域清晰可见；
- `partial`：部分被遮但仍能看到一部分；
- `covered`：口鼻主要区域被软物覆盖，只用玩偶模拟危险场景；
- `not_visible`：转头、俯卧、出画、过暗、严重模糊或被床栏挡住，无法判断。

### 3.3 姿态模型 V2

将行为模型改为可由单帧判断的姿态类别：

```text
lying
sitting
crawling_kneeling
standing
unknown
```

类别含义：

- `lying`：仰卧、侧卧或俯卧，身体主要处于躺卧状态；
- `sitting`：躯干直立但臀部承重；
- `crawling_kneeling`：四点支撑、跪立或爬行姿态；
- `standing`：躯干直立、腿部支撑，允许扶栏；
- `unknown`：严重遮挡、裁剪错误、姿态边界不清或不应强判。

计划中的固定类别顺序保存在 `templates/posture_classes_v2.txt`。后续训练、导出、板端枚举和协议显示均应读取或生成自这份顺序，不允许各自手写另一份。

如果第一轮 `sitting` 与 `crawling_kneeling` 数据不足，可以先合并为 `upright_not_standing`，但 `standing` 必须保持独立。类别表一旦确定，训练、TFLite、RUHMI、板端枚举和服务器显示必须引用同一份标签清单。

### 3.4 时序状态

以下内容不再作为单帧分类标签：

```text
quiet
active
sleeping
edge_grab
climbing
out_of_bed
```

它们由时序或多模态融合生成。

## 4. 需要采集的五类数据

### 4.1 目标检测图片

必须覆盖：

- 婴儿在中心、四条边和四个角；
- 仰卧、侧卧、俯卧、坐、跪爬、站立；
- 头朝不同方向、头部小目标、部分出画；
- 毛毯摊开、卷起、覆盖身体不同面积；
- 枕头、毛绒玩具和衣物等软物；
- 照护者的手、手臂、半身和全身；
- 空床、只有被褥、只有照护者、画面模糊和曝光异常；
- 白天、弱光、夜间、背光和局部阴影；
- 至少三套颜色和纹理差异明显的床品。

玩偶数据用于最终设备域适配，公开真实婴儿数据用于保持真实外观泛化。不能只用玩偶完成最终安全性能结论。

### 4.2 口鼻 ROI

四类均衡采集，尤其补足容易混淆的边界：

- `clear` 与薄纱、阴影、肤色被褥；
- `partial` 的 10%、30%、50% 逐级覆盖；
- `covered` 的不同覆盖物、方向和褶皱；
- `not_visible` 中的侧脸、后脑、俯卧、出画和低质量画面。

所有危险覆盖只允许使用玩偶。边界帧逐帧审核，不能把整段视频自动赋同一标签。

### 4.3 姿态 ROI

每个姿态必须同时覆盖中心和床边，避免模型把“位置”学成“姿态”：

| 姿态 | 中心 | 边缘 | 四角 | 有毛毯 | 照护者在场 |
| --- | --- | --- | --- | --- | --- |
| lying | 必须 | 必须 | 必须 | 必须 | 必须 |
| sitting | 必须 | 必须 | 建议 | 必须 | 必须 |
| crawling_kneeling | 必须 | 必须 | 建议 | 必须 | 必须 |
| standing | 必须 | 必须 | 必须 | 建议 | 必须 |
| unknown | 必须 | 必须 | 必须 | 必须 | 必须 |

`standing` 正样本要看到真正直立结构，不要只把靠床边或手碰床栏标为站立。

### 4.4 安静/活动时序片段

每段保存 20～60 秒同步数据，保留原始时间戳：

- 串口摄像头 JPEG 序列；
- 婴儿框中心、宽高、面积和置信度；
- 16×16 压力矩阵及压力中心；
- HTPA 80×64 原始温度矩阵；
- 五路温度、传感器健康状态和丢帧信息；
- 可选未来边缘称重/重力传感器原始值。

需要采集：

- 完全静止；
- 呼吸或很小的局部动作；
- 缓慢翻身；
- 连续四肢活动；
- 从躺到坐、从坐到站等转换；
- 照护者移动玩偶或被褥；
- 摄像头轻微抖动但婴儿不动；
- 被子移动但婴儿不动。

时序标签以一段时间为单位，而不是给单张图标 `quiet/active`。

### 4.5 床边风险片段

必须同时采正样本和更多硬负样本。

正样本：

- 站立并扶床栏；
- 站立后持续向外侧移动；
- 跪立到站立并在边缘保持；
- 边缘载荷逐渐增加；
- 模拟翻越和离床过程，只用玩偶并确保设备安全。

硬负样本：

- 躺在边缘；
- 坐在边缘；
- 手臂碰床栏但没有站立；
- 爬行经过边缘后返回；
- 毛毯堆在边缘；
- 照护者站在床边；
- 站立在画面中央；
- 摄像头偏移导致框靠画面边缘；
- 压力边缘高但视觉姿态是躺卧；
- 视觉似站立但压力仍在中心。

硬负样本数量应不少于正样本的 2 倍，这是压低“什么都判扒边”误报的关键。

## 5. 建议采集规模

### 5.1 第一轮工程迭代

| 数据 | 最低目标 |
| --- | ---: |
| 场景检测 | 2,000 张审核后图片，多标签框计数可重叠 |
| 口鼻遮挡 | 每类 500 个审核后头部 ROI |
| 姿态 | 每类 500 个审核后婴儿 ROI，`standing` 建议 800 |
| 安静时序 | 60 段，每段 20～60 秒 |
| 活动时序 | 60 段，每段 20～60 秒 |
| 状态转换 | 40 段 |
| 扒边/翻越正样本 | 50 段 |
| 床边硬负样本 | 至少 100 段 |

第一轮的目标是暴露标签和规则问题，不是证明产品已达到安全级性能。

### 5.2 后续稳定版本

- 场景检测扩展到 6,000～10,000 张有效图片；
- 每个遮挡和姿态类别扩展到 1,500～3,000 个独立 ROI；
- 每类时序状态至少 100 个独立场次；
- 增加不同真实主体、不同床品、不同房间和不同相机批次；
- 用真实婴儿数据时必须取得监护人同意并遵守隐私与安全要求，危险场景仍只用玩偶。

## 6. 场次设计与命名

每个场次只安排一个主要变量，建议命名：

```text
YYYYMMDD_subject_camera_bed_light_pose_zone_motion_take
```

示例：

```text
20260728_doll01_ra8cam_bedA_dim_standing_leftedge_quiet_01
```

每个场次至少保存：

```text
session_id
subject_id / doll_id
camera_id 和固件版本
相机高度、俯角、旋转、镜像设置
床边 ROI 标定版本
bed_set、lighting、room_id
posture、position_zone、airway、motion
caregiver_present
pressure / thermal / edge_load 是否有效
开始和结束时间
异常、断线、重置、丢帧备注
```

当前服务端各数据通道可独立开始和停止。做多模态场次时，所有通道使用相同的 `scenario_id` 前缀，并把同一个 `session_id` 写入实验备注；开始顺序建议为压力、热成像、视觉，停止顺序相反。后续可再把服务端改成“一键同步场次”。

`multimodal_capture_plan_v2.csv` 是覆盖矩阵，不是命令输入文件。其中 `mixed`、`varied` 和 `all_edges` 表示要拆成多个实际场次；调用 `capture_session.py` 时，`lighting` 仍只能填写 `day`、`dim` 或 `night_ir` 中的一个。

## 7. 标注规则

### 7.1 帧级标注

使用 `templates/frame_annotations_v2.csv`：

- 场景框坐标；
- 口鼻遮挡标签；
- 姿态标签；
- 婴儿所在床区；
- 图像质量和排除原因。

姿态裁剪应来自审核后的 `infant` 框，头部裁剪应优先来自审核后的 `head_face` 框。自动框只能预标，不能直接当真值。

### 7.2 段级标注

使用 `templates/multimodal_sequence_annotations_v2.csv`：

- 以毫秒记录段起止；
- 标记姿态、位置、运动和床边事件；
- 标记各传感器是否有效；
- 不能确定时使用 `unknown`，不要强行归入危险类。

### 7.3 数据划分

训练、验证、测试必须按场次和主体分组：

- 70% 场次训练；
- 15% 场次验证；
- 15% 场次测试；
- 同一录像的相邻帧不得跨集合；
- 至少保留一个主体或玩偶、一套床品、一个光照组合只用于测试；
- 多模态片段的所有通道必须进入同一个 split。

## 8. 新融合逻辑的初始设计

以下阈值只用于启动实验，必须用采集数据重新标定。

### 8.1 视觉运动特征

对最近 2～5 秒的婴儿框计算：

```text
中心点速度
框面积变化率
相邻框 IoU 下降
姿态类别变化次数
检测丢失比例
```

相机固定后，对这些量做中值滤波。摄像头整体抖动应通过背景或多个目标的共同位移抵消。

### 8.2 压力与热成像运动特征

压力：

```text
相邻矩阵绝对差总量
压力中心速度
边缘载荷比例
载荷向外移动趋势
```

热成像：

```text
人体热目标质心速度
热目标面积变化
热目标与视觉婴儿框映射后的位置一致性
```

当前 HTPA IPC 只提供原始 80×64 点阵和统计值，热目标质心需要后续在 CPU0 增加计算字段。

### 8.3 安静与活动

建议使用带迟滞的窗口分数：

```text
motion_score = visual_motion + pressure_motion + thermal_motion

ACTIVE:
  2～3 秒内多次超过进入阈值

QUIET:
  视觉、压力和热目标连续 5～10 秒低于退出阈值

SLEEPING:
  presence=PRESENT
  且 QUIET 持续更长时间
  且最近无哭声
```

单个传感器故障时降低置信度，不用旧值继续判定。

### 8.4 扒边和翻越

建议把风险分级为：

```text
EDGE_NEAR:
  婴儿框持续进入标定床边 ROI
  且压力中心/边缘载荷支持

EDGE_STANDING:
  EDGE_NEAR
  且 standing 高置信持续 1.5～2 秒

EDGE_CLIMBING:
  EDGE_STANDING
  且压力/未来边缘称重持续向外增加
  或检测到明确越栏轨迹

OUT_OF_BED:
  曾经在床
  随后压力释放
  且视觉/热目标跨越边界或消失轨迹支持
```

`standing` 不能单独触发扒边；婴儿框靠边也不能单独触发扒边。未来的边缘重力/称重传感器应保存原始值并先做空载、中心载荷和边缘载荷标定，不要直接假定单位为 N 或 kg。

## 9. 评估与放行门槛

不能只看总体准确率。至少输出：

- 检测模型每类 AP、召回率和小目标头部召回；
- 遮挡和姿态模型的逐类 precision、recall、F1 和混淆矩阵；
- 浮点模型与 INT8 模型逐类差异；
- 时序状态的片段级召回、误报次数/小时和确认延迟；
- `edge_grab/climbing` 在硬负样本上的误报率；
- 夜间、不同床品、不同相机偏移的独立结果；
- 传感器缺失时的降级行为。

第一轮建议的工程门槛：

```text
standing 在独立场次测试集 recall >= 0.90
standing precision >= 0.90
床边硬负样本误报率 < 5%
最终 EDGE_CLIMBING 在硬负片段上 0 次误报后再进入长时间测试
```

这些是原型迭代门槛，不是医疗或安全认证指标。

## 10. 执行顺序

1. 固定 RA8 串口摄像头的位置、方向、曝光和床边 ROI。
2. 使用 `multimodal_capture_plan_v2.csv` 完成第一轮场次。
3. 标注场景框、遮挡和姿态，先审计标签，不急于训练。
4. 用硬负样本重训姿态模型，彻底移除单帧 `edge_grab`。
5. 锁定一份标签清单，并同步更新训练配置、板端枚举、协议和服务器文案。
6. 从同步片段计算视觉框、压力和热目标运动特征。
7. 离线回放融合规则，确定进入阈值、退出阈值和持续时间。
8. 部署到 RA8 后做连续硬件回放和真实场景长时间误报测试。

在第 4 步完成前，当前模型的 `edge_grab` 只能作为调试概率显示，不能作为单独告警依据。
