# 玩偶图像采集与设备微调方案

## 目标和原则

公开数据负责让模型学习“真实婴儿的外观和姿态”，玩偶数据负责让模型适应最终摄像头、安装角度、床栏、被褥、夜视红外和宿舍光线。玩偶不能替代真实婴儿测试，因此不要把全部公开数据换成玩偶数据。

第一轮不追求复杂拍摄。每个场次 30～60 秒，取 1～2 FPS，改变姿态后再拍下一场。比连续保存上千张几乎一样的帧更有效。

严禁为了采集 `covered` 而遮盖真实婴儿口鼻。危险姿态只能用玩偶模拟。

## 先确认最终摄像头

优先级如下：

1. 最终直接接入 RA8P1、用于模型推理的摄像头。
2. 相同型号、相同镜头和相同安装位置的临时采集链路。
3. ESP32-S3 摄像头只能作为临时预采集，场次中标记 `camera_id=esp32s3_provisional`。

如果用 S3 拍摄训练、最后改成 RA8 摄像头，必须重新补最终摄像头数据，且 S3 数据不能作为最终测试集。

固定以下参数后再大量采集：

- 镜头高度、俯角、旋转方向；
- 分辨率、曝光、白平衡、增益；
- 夜间红外灯位置和亮度；
- 床边安全 ROI；
- 摄像头遮挡和失焦检测方式。

## 宿舍第一轮最小采集表

直接复制 `templates/capture_plan.csv` 使用。建议至少准备两套被褥/床单，一只玩偶即可。

### 场景检测

| 内容 | 目标有效帧 | 怎么摆 |
| --- | ---: | --- |
| 空床白天/夜间 | 各 120 | 被子摊开、卷起、枕头不同位置 |
| 中心区域婴儿 | 300 | 仰卧、侧卧、俯卧、头朝不同方向 |
| 左右/上下边缘 | 300 | 身体框进入固定边缘 ROI |
| 被子与软物 | 300 | 被子覆盖身体不同面积，玩具/枕头放不同位置 |
| 照护者 | 200 | 手、手臂、半身进入画面；不要只拍一种衣服 |

这些帧用于五类框标注。空床图可作为明确负样本，但必须来自自采场次，不能把 CribHD-C 无标注图片自动当作空床。

### 口鼻遮盖四分类

第一轮每类至少 250 个审核后 ROI：

- `clear`：口鼻区域完整可见。
- `partial`：被子、手或软物遮到一部分，但仍能看到部分口鼻。
- `covered`：明显覆盖主要口鼻区域；只用玩偶。
- `not_visible`：转头、俯卧、过暗、头在床栏后或图像质量不足。

每一类都要覆盖：

- 白天、弱光、夜间红外；
- 仰卧、侧卧、俯卧；
- 两套不同颜色/纹理的被褥；
- 画面中心和靠边位置。

不要按“这一整段录像就是 covered”直接批量标注。逐帧看头部 ROI，边界帧宁可标 `partial` 或暂时排除。

### 行为五分类

第一轮目标：

| 类别 | 有效 ROI | 采集方式 |
| --- | ---: | --- |
| `quiet` | 300 | 姿态稳定、无照护者 |
| `active` | 300 | 每隔 1～2 秒改变四肢和身体姿态 |
| `edge_grab` | 300 | 手臂/上身接近、接触或越过床边 ROI |
| `caregiver` | 250 | 照护者手臂/身体正在调整玩偶或被褥 |
| `unknown` | 350 | 模糊、严重遮挡、空床误裁、姿态不明确、模型不应强判的情况 |

单帧 `active` 只能表示明显动作姿态证据；最终清醒和睡眠仍由多帧状态机判断。

## 每次采集的实际步骤

1. 把摄像头固定在最终位置，关闭会自动变化且板端无法复现的滤镜。
2. 选择唯一场次名，例如 `night_set_b_edge_02`。
3. 摆好玩偶、被子和软物，录制 30～60 秒。
4. 每 1～2 秒改变一次姿态；不要快速晃动制造大量模糊帧。
5. 用 `capture_session.py` 取 2 FPS并去掉相邻近重复帧。
6. 检查 `session.json` 的摄像头、光照、被褥和玩偶 ID。
7. 场景框用 CVAT 标；分类 ROI 用 `frame_annotations.csv` 标。
8. 标完先运行 `prepare_scene_dataset.py` 和 `prepare_roi_datasets.py` 看审计报告。
9. 抽查每类至少 50 张裁剪图，确认框没有切掉头部、标签没有错位。

## 数据划分

同一视频或同一场次的所有帧必须在同一 split。建议：

- 70% 场次：训练；
- 15% 场次：验证；
- 15% 场次：测试。

如果只有一只玩偶，至少为每个标签独立拍 3～5 个场次，再按场次拆分。最好把一种被褥或一种夜间角度只放到测试集，用来检验泛化。

公开 SyRIP 优先保留官方划分，但整理器会把官方 train/val 中重复的
`image_source` 整组隔离到验证集；不可把同一来源的相邻视频帧拆到不同集合。

## 训练顺序

### 场景检测

1. 用 YOLOX-Tiny COCO 官方权重初始化。
2. 用 CribHD + SyRIP 训练基础模型。
3. 加入自采玩偶数据，低学习率继续微调。
4. 混合批次目标约为 70% 公开数据、30% 自采数据；本地数据过少时可重复采集场次条目，但不要复制测试集。
5. 最后 10～15 epoch 关闭 Mosaic，重点验证小头部框和边缘区域。

玩偶在场景检测阶段可以标 `infant`，但每个训练周期必须继续保留真实婴儿公开数据，避免模型只认识玩偶材质。

### 两个分类模型

1. 从 ImageNet MobileNetV3-Small minimalistic 权重开始。
2. 先冻结 backbone 训练分类头。
3. 再只解冻末端约 30 层，使用 `1e-5` 低学习率微调。
4. INT8 校准样本必须混合白天、夜间、各类被褥和各个类别。
5. 比较浮点与 INT8 混淆矩阵；量化后某个风险类别召回明显下降就不能上板。

## 如何判断第一轮数据够不够

满足以下条件才进入板端集成：

- 每个分类类别在训练/验证/测试中都有独立场次。
- 检测数据审计无缺图、无非法框、无类别映射错误。
- `covered`、`edge_grab` 的测试召回优先于总体准确率。
- `not_visible` 和 `unknown` 能吸收无法判断的画面，而不是强判危险或安全。
- 夜间红外测试单独统计。
- 在从未见过的被褥和相机轻微偏移下仍能工作。

真实婴儿性能只能通过合规、监护人同意的独立真实数据评估。玩偶测试通过只表示工程链路和场景规则可用，不表示真实婴儿安全监测已经验证。
