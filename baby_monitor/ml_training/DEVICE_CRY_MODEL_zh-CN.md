# RA8P1 第一层哭声检测模型

## 本次数据

设备实录位于 `data/selected/1`，命名规则会被流水线严格校验：

- `CTR` / `NTR`：训练集。
- `CVA` / `NVA`：验证集。
- `CTE` / `NTE`：测试集。
- `cry`：哭声。
- `QT`：安静环境，归入非哭声。
- `TK`：说话环境，归入非哭声。

本批共 123 个滚动分卷、约 61.7 分钟，全部为 16 kHz、单声道 WAV；
16 个分卷标为哭声，107 个分卷标为非哭声。RA8 大多每 30 秒关闭当前 WAV
并新建下一个文件，因此这些文件并不是 123 次相互独立的实验，而是
`哭声 / 安静 / 说话 × train / validation / test` 共 9 个连续播放采集会话。
一个分卷中也可能串有多条同标签的公开音频。

训练仍按 1 秒窗口、250 ms 步长切分；同一分卷不会跨划分，同一连续会话使用
相同 `group_id`，评估报告不再把每个 30 秒分卷夸大成独立采集。最终清单共
5,837 条记录，其中 5,571 条通过校验，按组划分为 3,908/834/829 条
train/validation/test，未发现跨划分组泄漏。除原有数据外，本轮加入了
InfantCry-DBL Tier 2、TUT Rare Sound Events，以及 1,439 条通过校验的
RAVDESS 成人情绪语音。RAVDESS 按说话人固定划分为 16/4/4 人，专门作为喊叫、
高声说话和情绪语音硬负样本，避免同一说话人跨集泄漏。其许可证为
CC BY-NC-SA 4.0，仅适合当前研究和非商业实验。

第一层最终特征集含 166,655/10,511/10,784 个 train/validation/test 窗口；
训练时同时生成一份通用噪声、一份 RA8 分块 RMS/滤波/增益链模拟，以及一份
120--700 ms、低信噪比短哭声混合样本，用于兼顾小声、短促哭声和喊叫误报。

## 训练与量化结果

部署候选是 `49 x 10 x 1` MFCC 输入的紧凑 MLP，使用 1 秒窗口和 250 ms
步长。板端 C 权重、输入和中间激活均为 INT8，累加为 INT32；本轮候选、量化
报告和阈值扫描在 `artifacts/cry_detection_mlp_hardneg_v2b`。

关键离线结果：

- 浮点模型全部独立测试窗口：准确率 92.54%，哭声召回率 93.64%。
- 自定义 INT8 后备实现：准确率 92.57%，窗口混淆矩阵为
  `[[7349,622],[179,2634]]`，量化没有造成可见退化。
- 阈值 0.65、最近 8 窗至少命中 3 窗时，RA8P1 留出记录为
  `TN/FP/FN/TP = 18/0/0/3`；RAVDESS 留出 4 名说话人的 240 段记录为
  `240/0/0/0`，本轮喊叫硬负样本没有录音级误报。
- 全来源验证记录在同一策略下为 `TN/FP/FN/TP = 471/53/83/227`。这说明
  新阈值解决了当前设备喊叫误报，但不同房间、距离和真实婴儿哭声仍需继续
  进行独立实物回归，不能只依据训练集结果。
- 嵌入式 MFCC 与训练 MFCC 的三类实录最大绝对误差不超过
  `2.4e-6`。

更强的 DS-CNN 也已训练并导出为严格 INT8。其 TFLite 大小为 31,504
字节，Vela 报告 0 个 CPU 算子、17.61 KiB SRAM 和 691,732 MAC；
产物位于 `artifacts/cry_detection_device`。当前 FSP 工程尚未集成
TFLM/Ethos-U 运行时，所以第一轮实物验证先运行已独立验证的 Cortex-M85
INT8 后备模型，不修改 `configuration.xml`。

## 板端行为

麦克风仍在原有高优先级采集线程中工作。推理使用独立低优先级静态任务，
每 250 ms 复制最近 1 秒音频，采集线程可以在 MFCC 和模型计算期间继续运行。
板端复用了 SD 录音的声道、DC、增益、限幅、带通和分块 RMS 处理，确保输入
与本次实录数据一致。

板端不再要求哭声连续出现。最近 8 个窗口中只要有 3 个概率达到 0.65，
就确认哭声；确认后每次新命中都会把释放保持恢复为 12 个窗口，约 3 秒。
这样哭声中间的换气、短暂停顿或弱音不会让计数立即归零。融合层仍保留自己的
1.5 秒危险状态去抖；温度、离床、边缘、传感器故障等原有安全规则未被模型
替换。

本次从 0.50 上调到 0.65，并加入成人喊叫硬负样本。现有设备留出测试保持
3/3 哭声记录命中，同时把非哭声误报从 3/18（阈值 0.50）降到 0/18；
RAVDESS 留出记录从 4/240 个误报降到 0/240。3/8 投票和短哭声释放保持不变，
因此不是简单压低所有短声音，而是同时修正训练分布和单窗口门限。

网页“多模态推理”参数组新增字段：

| 字段 | 含义 |
| --- | --- |
| `cry_ready` | `1` 表示推理任务已创建 |
| `cry_n` | 已完成的推理窗口数，应持续增长 |
| `cry_raw` | 原始哭声概率乘 1000，例如 `823` 表示 82.3% |
| `cry_run` | 最近 8 个窗口中的命中数，范围 0～8 |
| `cry_ok` | `1` 表示已经通过 3/8 滑动投票或处于释放保持期 |
| `cry_hold` | 距离释放确认状态还剩多少个无命中窗口，最大 12 |
| `cry_ms` | 最近一次 MFCC 加模型计算耗时，单位毫秒 |
| `cry` | 送入融合层的 0–100 置信度 |

`state=6` 时网页安全状态显示“哭声”。若其他更高优先级安全规则正在生效，
`state` 可能不是 6，但仍可用 `cry_ok=1` 和 `cry` 判断哭声模型是否命中。

## 第二层原因分类（实验）

旧分类模型偏向 `hungry` 的根因不是网页映射，而是旧公开数据类别极度失衡且
标签来源不一致：在独立公开测试集上的平衡准确率只有 17.6%，其余四类召回率
接近零。`data/selected/2` 的 55 个 WAV 是少量同标签音频连续播放后形成的
滚动分卷，不能把同一会话中的窗口当成大量独立样本。本轮将它们作为 RA8
回放设备域适配数据，与 InfantCry-DBL Tier 2 一起训练，并给设备域 4 倍源
权重；设备域结果因此只能验证适配是否生效，不能冒充独立泛化精度。

新版使用 InfantCry-DBL v1 的 Tier 2 数据，按匿名录音/婴儿分组后再切分，
避免同一来源跨训练、验证和测试集。标签按数据集的五种声学提示映射到当前
固件顺序：

```text
neh -> hungry
eairh -> belly_pain
heh -> discomfort
owh -> tired
eh -> burping
```

当前模型输出 5 类：

```text
hungry / belly_pain / discomfort / tired / burping
```

`unknown` 不是强行训练的第六类，而是板端拒绝机制。板端最多滚动平均最近
8 个哭声窗口，从第 3 个有效窗口开始就可以给出分类；最高平均概率至少
0.55、且第一名比第二名至少高 0.10 时输出原因，否则显示 `unknown`。

Keras 模型在独立 Tier 2 测试集的 993 个窗口上准确率 68.48%、平衡准确率
64.73%。Cortex-M85 C INT8 模型在 1,018 个独立 Tier 2 验证窗口上准确率
74.56%；采用最少 3 窗、置信度 0.55、差值 0.10 后，211 段验证录音的覆盖率
为 76.30%，被接受结果准确率为 93.79%，把拒识也计错时准确率为 71.56%。
参与训练的 55 个 RA8 回放记录对应 2,194 个窗口，窗口准确率为 95.03%，
覆盖率为 90.91%，但这不是独立测试。`tired` 的设备域录音仍只有 5 条，出现
`unknown` 时应优先继续采集独立设备实录，而不是继续降低拒识门限。
模型 SHA-256 前缀为 `f56ac320832341d0`；一级模型前缀为
`9820a8b329274ac7`。

这些类别来自婴儿发声的声学提示标签，并不是经过临床确认的哭声原因。分类
结果仍只作为网页上的实验参考，不参与安全状态或融合决策，也不能作为医疗
判断。扬声器播放到 RA8 麦克风还存在设备、房间和距离的域差异，最终效果必须
用烧录后的独立播放实验确认。

新增分类字段：

| 字段 | 含义 |
| --- | --- |
| `cry_type_exp` | 固定为 `1`，表示这是实验输出 |
| `cry_type_ready` | 分类模型已就绪 |
| `cry_type_n` | 当前哭声会话已累计的有效分类窗口，最多 8 |
| `cry_type` | 通过拒绝门限后的英文类别，否则 `unknown` |
| `cry_type_ok` | `1` 表示类别通过置信度和差值门限 |
| `cry_type_conf` | 最高平均概率乘 1000 |
| `cry_type_margin` | 第一、第二名平均概率差乘 1000 |
| `cry_type_hu/bp/dc/ti/bu` | 五类平均概率，均乘 1000 |

## 烧录后测试

RFP 使用以下两个已验证产物：

| 核 | 文件 | 大小 | SHA-256 |
| --- | --- | ---: | --- |
| CPU0 | `Multicore_top_CPU0/Debug/Multicore_top_CPU0.srec` | 413198 字节 | `437D63B233CA3A1CE9B49268B3044C4A7CF2AA4BED3EFA9367E5F325EF54C3E8` |
| CPU1 | `Multicore_top_CPU1/Debug/Multicore_top_CPU1.srec` | 261454 字节 | `72DC4B068C70D478731028545F0BBDDA604DD702F103C005B186D4BAFB790CD3` |

1. 用 RFP 同时烧录 CPU0 和 CPU1 的 `Debug` 目录内 SREC。
2. 完全断电再上电，等待麦克风自动启动约 3 秒。
3. 打开网页设备详情，确认 `cry_ready=1`。
4. 保持安静 10–20 秒：`cry_n` 应持续增长，`cry_ok` 应保持 0。
5. 正常说话 20–30 秒：记录是否出现连续误触发。
6. 播放没有参加训练的新哭声，扬声器距离先用约 1 米。新版分类模型优先使用
   `ml_training/data/ready_to_play/public_cry_wav/dbl_tier2_test_类别名.m3u`
   逐类测试；不要用 `train` 或 `validation` 列表冒充独立测试。
7. 连续播放至少 5 秒。命中可以是断续的；预期 `cry_run` 在最近 8 窗中
   累积到 3、`cry_ok=1`，随后网页显示“检测到哭声”或至少
   `inference.cry >= 75`。
8. 连续获得 3 个有效哭声窗口后即可开始显示分类；继续播放时
   `cry_type_n` 最多增长到 8，并使用滚动平均稳定结果。门限不足时仍会显示
   “未知”，这是对低可信结果的保留拒绝。
9. 停止播放后观察 `cry_hold` 从 12 下降；约 3 秒后 `cry_ok` 应恢复为 0，
   分类窗口和类别同时清空。

如果 `cry_ready=1` 但 `cry_n` 不增长，检查麦克风采集状态；若 `cry_n`
增长但 `cry_raw` 长期很低，保存这次 WAV 作为新的设备域困难样本。不要立刻
降低阈值，先分别记录安静、说话和哭声各 30–60 秒再重新评估，否则容易增加
宿舍环境误报。
