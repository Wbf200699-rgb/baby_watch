# App 架构与通信说明

## 客户端职责

App 连接服务端，不直接连接 ESP32 局域网摄像头。硬件负责采集和边缘安全判断，服务端负责设备接入、持久化、媒体转发和 AI 服务；App 负责数据展示、控制交互与用户告警。

## 模块划分

| 模块 | 主要文件 | 职责 |
| --- | --- | --- |
| 协议 | `MobileProtocol.kt` | 数据模型、JSON/二进制解析、融合与事件映射、端点 URL 策略 |
| 仓库 | `MobileServerRepository.kt` | 状态流、HTTP/SSE 编排、命令与事件、媒体控制器 |
| 网络 | `NetworkRuntime.kt` | OkHttp、超时与重试、网络状态观察 |
| 配置 | `ServerCredentialStore.kt` | 云端/本地双配置、Keystore 加密密码、事件游标 |
| 历史 | `MonitorHistoryStore.kt` | 按服务地址与设备隔离轻量趋势缓存 |
| 告警策略 | `SafetyEventNotificationPolicy.kt` | 事件生命周期去重与通知决策 |
| 页面 | `ui/` | 首页、监护、洞察、传感器、设置 |
| 后台 | `KeepAliveService.java` | 前台服务与监护连接生命周期 |

当前仓库采用共享状态仓库组织页面；媒体控制器仍与主仓库位于同一文件。后续可拆分模块并引入 ViewModel，而不应把当前实现描述为完整 Clean Architecture。

## 数据流

```text
HTTP 初始查询 / SSE 状态与事件 / WebSocket 音视频
                      ↓
              协议解析与有效性检查
                      ↓
        Repository StateFlow / 最新矩阵与媒体队列
                      ↓
            Compose 页面 / 历史缓存 / 通知
```

矩阵解析和媒体处理在后台执行。视频与矩阵可丢旧帧以保持时效；安全事件依据标识和生命周期处理，不能按视频帧的丢弃策略处理。

## 控制闭环

```text
用户操作 → HTTP 命令 → 服务端 → 网关 → RA8 执行
                                              ↓
App 更新界面 ← SSE / 状态回读 ← 硬件遥测确认
```

暖光、拍抚状态由硬件回读确认。摇篮曲和 AI 故事使用不同的请求与 UI 状态；故事生成和传输不等同于播放已经完成。

## 手动 Plan B

云端与电脑端分别保存配置。切换时取消旧请求与 SSE，关闭媒体连接，重建当前状态；generation 标识用于过滤旧连接迟到的数据。事件游标与历史按服务地址和设备隔离，控制命令不会跨端自动重放。

本地 HTTP 仅允许私网/回环字面 IPv4。默认网络观察仍依赖 Android 的默认网络；当离线 Wi-Fi 与蜂窝同时存在时，需确认手机没有切到蜂窝。任意局域网网络绑定、自动发现和自动故障转移尚未实现。

## 安全表达与边界

- 数据缺失、来源失效与状态正常分别显示。
- “已查看”是用户确认，不是风险解除；解除以硬件状态机为准。
- AI 解释不降低本地安全事件等级。
- 密码在本机加密保存；本地 HTTP 传输本身不加密。
- Android 后台服务受系统和厂商省电策略限制，长时间监护需真机验收。

## 验证入口

运行 `gradlew testDebugUnitTest lintDebug assembleDebug`。协议回归覆盖融合证据、原始/标准化字段、热成像温标、事件、执行器和端点策略；端到端时延、断线恢复、音视频负载和后台长稳测试按全流程测试指南执行。
